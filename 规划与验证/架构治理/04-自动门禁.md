# 自动门禁

## 一、现有入口

```bash
python backend/scripts/audit_architecture_health.py \
  --god-lines 800 \
  --fan-in 20 \
  --fan-out 20 \
  --output 规划与验证/架构治理/architecture-health-latest.json
```

输出内容包括：

- 模块数量。
- 总行数。
- 巨石文件。
- 循环依赖。
- 高扇入和高扇出模块。
- 每个包的大小。

## 二、Python 依赖规则

建议采用 Import Linter：

```ini
[importlinter]
root_package = app

[importlinter:contract:models-independent]
name = Models must not import api or services
type = forbidden
source_modules = app.models
forbidden_modules = app.api, app.services

[importlinter:contract:schemas-independent]
name = Schemas must not import api or services
type = forbidden
source_modules = app.schemas
forbidden_modules = app.api, app.services

[importlinter:contract:services-not-api]
name = Services must not import API
type = forbidden
source_modules = app.services
forbidden_modules = app.api

[importlinter:contract:etl-not-api]
name = ETL must not import API
type = forbidden
source_modules = app.etl
forbidden_modules = app.api
```

后续增加 Domain 后，再启用 Layers 和 Independence 契约。

## 三、前端依赖规则

建议采用 dependency-cruiser：

- `pages` 不直接引用后端实现细节。
- `components` 不引用 `pages`。
- `api` 不引用 `pages` 和 `components`。
- `stores` 不引用页面。
- 禁止循环依赖。

## 四、棘轮策略

当前审计为 critical，不能直接让 CI 失败。采用棘轮：

1. 先保存基线。
2. 新提交不能增加巨石数量。
3. 新提交不能增加循环。
4. 不允许新增高扇出模块。
5. 每阶段允许把阈值逐步下调。

## 五、PR 门禁

每个 PR 必须展示：

- 架构审计 JSON 差异。
- 受影响领域的测试。
- 是否新增契约版本。
- 是否增加 legacy 分支。
- 是否降低巨石行数。

## 六、报告质量门禁

- 封面、判断、章节顺序。
- Block 指纹重复率。
- Claim 数字覆盖率。
- 图表与章节焦点一致。
- PDF 页数与章节数量一致性。
