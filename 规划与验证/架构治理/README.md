# 架构治理：模块爆炸与巨石治理

本目录解决当前项目“功能模块越来越多，但边界没有同步增强”的问题。目标不是拆成微服务，而是把现有系统演化成边界清楚、契约稳定、可自动审计的模块化单体。

## 当前判断

当前问题不是 LangGraph 或 SemanticPlan 方向错误，而是新能力没有按照业务边界归位：

- 服务层文件数量快速增加。
- 核心流程仍集中在少数巨石文件中。
- 多个领域互相引用，缺少单向依赖约束。
- 旧路径和新路径并存，维护面扩大。
- 有功能测试，但缺少持续执行的架构适应度门禁。

## 治理目标

```text
模块化单体
+ 明确业务边界
+ 稳定契约
+ 单向依赖
+ 自动审计
+ 渐进迁移
```

不做：

- 不为了“模块化”直接拆微服务。
- 不重写第二套主引擎。
- 不在没有测试保护时大规模移动代码。
- 不为短期通过门禁而隐藏依赖。
