# 迁移路线与任务清单

## P0：止血和冻结

### P0-1 建立架构健康报告

- 将 `audit_architecture_health.py` 接入 CI。
- 保存每次提交的 JSON 基线。
- 新巨石文件和高扇出模块必须解释原因。

### P0-2 清理循环依赖

处理：

```text
services/custom_report
services/report_planner
```

建议：

- 抽出 `report_plan_contract.py`。
- `report_planner` 只依赖契约。
- `custom_report` 只通过 planner Port 调用。

### P0-3 冻结契约

- SemanticPlan 版本号。
- Claim 版本和证据字段。
- Tool/Module 输入输出端口。
- ReportPlan 章节和 Block 契约。

### P0-4 拆 `judgment_service`

第一刀：

- `query_router.py`
- `claim_factory.py`
- `aggregation_claims.py`
- `comparison_claims.py`
- `ranking_claims.py`
- `distribution_claims.py`
- `correlation_claims.py`

`judgment_service` 保留 Facade，测试继续通过后再删除内部旧函数。

### P0-5 拆 `slice_report`

按输出阶段拆：

- `report_pipeline.py`
- `chapter_builders/`
- `report_chart_assembler.py`
- `pdf_render_service.py`
- `report_package_service.py`

### P0-6 建立文件大小棘轮

- 禁止新增超过 800 行的文件。
- 现有 10 个巨石只允许变小。
- 每个阶段提交前后记录行数。

### P0-7 报告门禁

- 封面页不吞页。
- 判断段在前。
- 章节顺序不漂移。
- Block 去重指纹 100% 生效。
- 焦点与章节一致。

## P1：模块化单体落地

### P1-1 建立 Domain 目录

按 Dialogue、Metrics、Reports、Data Sources、Identity 建立领域 Facade。

### P1-2 Ports / Adapters

先为以下能力定义 Port：

- LLM Provider。
- Repository。
- Retriever。
- Report Renderer。
- Data Source Connector。

### P1-3 依赖门禁

- Python 使用 Import Linter。
- 前端使用 dependency-cruiser。
- 禁止跨域直接引用实现模块。

### P1-4 RAG 和知识版本化

- 指标、阈值和业务规则带版本。
- 工具检索结果可回放。
- Claim 记录使用的目录版本。

### P1-5 审计回放

- 保存 SemanticPlan、DAG、工具版本和 Claim。
- 同一输入可回放同一验证结论。

## P2：Domain Pack 和新领域

- 抽出 Domain Pack 接口。
- 先用上市公司公开数据最小接入。
- 再增加描述、诊断、预测和情景模拟。
- 语音和移动端在主链稳定后再做。

## 每个阶段的完成条件

1. 对应功能测试通过。
2. 架构审计指标不恶化。
3. 契约兼容。
4. 旧路径有明确退役条件。
5. 新增文档记录迁移前后差异。
