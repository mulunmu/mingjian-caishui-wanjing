# 组合模块创新性与横向复用调研

日期：2026-09-17

## 一、结论先行

“把指标和模块组合起来”本身不是首创。

市场已经存在：

- 语义层和统一指标定义。
- 自然语言问数。
- Agent 工作流和状态图。
- 有向无环图任务编排。
- 对话上下文和长期记忆。
- 自动图表和报告生成。

因此不能把“我们使用了模块组合”本身包装成原创突破。

真正有潜力形成创新的，是以下组合：

```text
类型安全的模块契约
+ 受约束的动态组合规划
+ Claim 事实层和证据链
+ ConversationCase 长记忆
+ 对话/图表/报告共享同一组合骨架
+ 可替换领域包
```

更准确的说法是：

```text
我们提出了一套面向决策分析的、可验证、可追溯、可跨领域复用的组合式分析方法论和参考实现。
```

## 二、已有产品和技术

### Snowflake Cortex Analyst

来源：

- https://docs.snowflake.com/en/user-guide/snowflake-cortex/cortex-analyst

要点：

- 使用语义模型连接业务问题和数据库。
- 语义模型包含业务过程、指标和业务规则。
- 支持自然语言问数、自动选择数据源和受治理回答。

对我们的启示：

```text
自然语言不能直接面对数据库，必须先经过语义层。
```

### Cube Semantic Layer

来源：

- https://cube.dev/docs/product/semantic-layer

要点：

- 统一指标、维度、Join、权限和缓存。
- Agent 查询 Semantic SQL，而不是直接生成未治理 SQL。
- 同一个语义层服务 BI、应用和 AI Agent。

对我们的启示：

```text
组合系统的基础不是 RAG，而是稳定、可版本化的语义层。
```

### dbt MetricFlow

来源：

- https://docs.getdbt.com/docs/build/about-metricflow

要点：

- 用语义模型定义指标、维度和时间粒度。
- 强调指标定义的 DRY、一致性和复用。

对我们的启示：

```text
当前指标 Registry 的方向正确，下一步应补分析模式和分析任务定义。
```

### Microsoft Copilot for Power BI

来源：

- https://learn.microsoft.com/en-us/power-bi/create-reports/copilot-introduction

要点：

- 聊天分析依赖准备好的语义模型。
- 支持报告摘要、创建可视化和后续问题。
- 清理聊天上下文后，当前话题上下文被清空。

对我们的启示：

```text
长期记忆和当前任务上下文必须分层，不能把所有历史都塞进下一轮 Prompt。
```

### Databricks Genie

来源：

- https://docs.databricks.com/aws/en/genie/

要点：

- Genie Agents 由数据团队配置可信数据、指标和业务规则。
- 自然语言回答受治理数据约束。

对我们的启示：

```text
领域包必须包含可信数据、指标、规则和样例问题。
```

### Amazon Quick

来源：

- https://docs.aws.amazon.com/quicksight/latest/user/quicksight-q.html

要点：

- 自然语言聊天、结构化数据连接、可视化和研究报告。

对我们的启示：

```text
对话、分析、可视化和报告在产品层应是一个连续体验，而不是四个割裂页面。
```

### LangGraph Memory

来源：

- https://docs.langchain.com/oss/python/langgraph/add-memory

要点：

- 短期记忆是 thread 级 checkpoint。
- 长期记忆跨会话保存。
- 支持语义搜索、消息裁剪、摘要和检查点管理。

对我们的启示：

```text
长记忆应存 ConversationCase、Claim 和报告引用，而不是只缓存消息文本。
```

## 三、市场已有的“组合”

### 1. 指标组合

例如：

```text
营收同比 + 毛利率 + 现金流
```

这类能力在 BI 和语义层中很常见。

### 2. 工具组合

Agent 平台可以组合搜索、SQL、图表、通知等工具。

### 3. 工作流组合

LangGraph、Dagster、Airflow 等可以编排节点和依赖。

### 4. 报告组合

很多报告平台可以组合章节、表格、图表和文本块。

所以：

```text
只有模块组合，不足以构成独立创新。
```

## 四、我们可能形成的差异化

### 差异化一：模块不是普通工具，而是有类型的分析积木

每个模块声明：

```text
输入端口
输出端口
数据类型
依赖
权限
成本
场景约束
验证规则
```

这把“自由组合”限制在可执行、可验证的范围内。

### 差异化二：LLM 负责语义，确定性系统负责组合正确性

LLM 可以提出：

```text
分析目标
候选指标
比较范围
潜在分析模式
```

但不能直接决定任意工具拼接。

Plan Compiler 负责：

```text
端口兼容
依赖顺序
去重
预算
执行图
回退
```

### 差异化三：Claim 是跨对话、图表和报告的统一事实单位

同一 Claim 可以进入：

```text
对话结论
可视化
报告 Block
审计日志
长期记忆
```

这形成了统一证据链。

### 差异化四：ConversationCase 让长记忆与报告联动

用户对旧结论追问时，系统恢复：

```text
范围
指标组合
分析模式
Claims
图表
报告引用
```

这不是简单记忆聊天，而是记忆“分析案例”。

### 差异化五：领域包和引擎分离

核心引擎不应绑定财税领域。

领域包负责：

```text
实体定义
指标定义
维度和时间粒度
阈值和业务规则
分析模式
可视化和报告模板
权限和政策
```

## 五、横向迁移到其他数据的条件

只要一个领域能定义：

```text
实体
指标
维度
时间
阈值
分析模式
决策动作
```

这套骨架就可以迁移。

可能迁移方向：

- 供应链风险。
- 制造业质量分析。
- 能源设备运维。
- 医疗运营分析。
- 教育质量分析。
- 销售和客户经营分析。
- 产业园区招商与企业服务。

但迁移不是“换一份数据”这么简单。必须为每个领域建立独立 Domain Pack。

## 六、系统分层建议

```text
Core Engine
  - Intent
  - AnalysisPattern
  - Module Graph
  - Claim Guard
  - Visual Planner
  - Case Memory
  - Report Composer

Domain Pack
  - Entity Schema
  - Metric Registry
  - Dimension Registry
  - Threshold Registry
  - Scenario Library
  - Analysis Pattern Library
  - Report Template

Connector Layer
  - Database
  - Excel
  - API
  - Object Storage
  - Knowledge Base
```

## 七、商业模式

### 垂直产品

以财税风控作为第一个垂直产品，面向银行、税务师事务所、园区和企业集团。

### 平台产品

将组合引擎、Case Memory 和 Report Composer 作为平台能力，领域包可单独交付。

### 领域包

每个行业或数据域销售独立 Domain Pack，包括指标、阈值、分析模式和报告模板。

### API 和私有化

向机构和软件厂商提供分析 API、嵌入式分析和私有部署。

## 八、创新声明怎么表述才可信

不推荐：

```text
我们发明了模块组合。
我们发明了 RAG。
我们发明了 Agent 工作流。
```

推荐：

```text
我们提出一种面向决策分析的、类型安全且可验证的组合式分析框架，
将语义意图、可执行分析模块、Claim 事实、长记忆和报告 Block 统一到同一证据链，
并通过财税风控数据完成参考验证。
```

## 九、要形成真正创新，必须补的证据

1. 形式化模块契约和组合约束。
2. 组合正确性和可执行性证明。
3. 与单指标查询、固定模板和直接 LLM 的消融对比。
4. 长对话跨话题恢复实验。
5. 报告去重和分页验证。
6. 用户研究：决策时间、理解度、信任度和报告修改时间。
7. 至少一个非财税领域的 Domain Pack 迁移实验。

## 十、最终判断

当前数据是跳板，不是终局。

这套系统的潜在价值不是“财税风控问答”，而是：

```text
一套可复用的决策分析操作系统：
领域数据进入 Domain Pack，
语义意图进入 AnalysisPattern，
执行结果进入 Claim，
对话和报告共享 Case。
```

如果只停留在财税问答，价值会被垂直数据限制。  
如果把引擎、领域包和证据链分层，它就有机会成为面向多行业数据决策的平台型方法论和产品骨架。
