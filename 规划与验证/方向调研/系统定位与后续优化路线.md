# 明鉴财税风控系统定位与后续优化路线

日期：2026-09-17（不含语音与手机端）

## 一、系统定位

本系统不是通用聊天机器人，也不是让 LLM 直接给出税务或法律结论的黑盒工具。

更准确的定位是：

```text
基于真实企业数据、指标口径和阈值知识，
提供可追溯财税风控分析、动态工具组合、风险解释与模块化报告生成的决策辅助系统。
```

核心价值不在“模型会不会聊天”，而在四件事：

1. 数据和指标口径可信。
2. 分析过程可解释、可追溯。
3. 对话能根据场景动态组合工具，而不是固定菜单。
4. 报告由指标、Claim 和章节模块组成，不是一次生成整篇自由文本。

系统不承诺：

- 代替税务机关、司法机关或审计机构作出最终认定。
- 在没有数据源时编造企业、数字、风险结论或行业名单。
- 用 LLM 自由生成不可追溯的财务事实。

## 二、当前已经形成的能力

- 语义主路径：意图、主体、业务域和任务类型分层识别。
- 混合 RAG：结构化工具召回、指标别名、场景和阈值知识。
- 动态组合：开放概览可从候选指标生成 DAG；多指标可并行执行。
- Claim 事实层：数字、企业、评级和风险结论来自确定性执行。
- LangGraph 外层：状态机、检查点、报告审批、Agent 轨迹。
- 长期会话：话题记忆、跨轮引用、实体和报告关联。
- 报告 Block：章节和段落模块可锁定、重排、重生成、恢复版本。
- 过程可视化：SSE 展示识别、召回、组合、执行和校验阶段。
- 可视化：根据工具输出生成雷达图、柱状图等。

## 三、当前主要缺口

### 数据和指标

- 36 个 unsupported 指标缺少真实源字段、时间序列或明细数据。
- 不能用模型补造；必须补数据源、公式、执行器、别名和测试。

### 动态组合

- 当前最先落地的是候选指标并行组合。
- 阈值算子、趋势算子、对比算子和 Verifier 还没有全部接入执行器。
- 下一阶段需要把“指标 -> 阈值 -> 算子 -> 验证 -> Claim 聚合”做成可执行图。

### 知识层

- 能力、分析流程、行业分类、指标口径和报告方法仍需要更完整的知识 RAG。
- 当前 FAQ 和方法论回答已经能由 LLM 表达，但知识覆盖仍需继续扩展。

### 金融模型

- 当前金融模型是可选复核层，未成为必经路径。
- 当前硬件不适合生产部署 13B 本地模型。
- 优先保持 API 复核，待真实报告场景验证后再决定本地模型投入。

### LangChain

- 没有作为独立核心编排层接入。
- 当前使用 LangGraph 管外层状态，保留 LangChain 作为未来模型和工具适配器选项。
- 不应为了技术栈完整而重复建设 Planner、RAG 和 Claims。

## 四、后续优先级

1. 增加真实数据源，逐步关闭 36 个 unsupported 指标。
2. 扩展动态 DAG 的非指标模块执行器。
3. 建设版本化知识 RAG：能力、流程、行业、口径、方法论、报告。
4. 增加对话与报告黄金集，覆盖开放分析、追问、跨话题、组合和报告章节。
5. 继续优化报告 Block 编辑器，让用户调结构和章节组合，而不是改事实数字。
6. 继续提升首字延迟、RAG 召回质量和缓存命中率。
7. 增加生产监控、审计日志和异常回放。
8. 在真实场景验证后再评估金融模型的 API 或本地部署。

## 五、优化红线

- 新增指标必须同时具备源字段、公式、执行器、RAG 条目和边界测试。
- 新增模块必须声明输入、输出、依赖、成本、权限和验证规则。
- 不允许新增只通过单元测试、没有进入生产入口的功能。
- 不允许用固定文案替代正常 LLM 表达；固定文本只能用于安全拒绝或基础设施故障。
- 不允许让 LLM 生成数字、企业名单、评级或最终风险结论。
- 每次组合能力变更都必须有真实 HTTP、数据库和页面级证据。

## 六、面向大创与设计赛的商业表达

### 目标客户

- 银行小微信贷、供应链金融和融资租赁的初审团队。
- 税务师事务所、会计师事务所和财税咨询机构。
- 产业园区、招商部门和中小企业服务平台。
- 需要批量筛查企业经营、税务和发票风险的企业集团。

### 客户痛点

- 财务、税务、发票和外部风险数据分散，人工核对耗时。
- 通用大模型可以聊天，但数字不可追溯，无法直接用于风控判断。
- 传统风控系统报告固定，无法按场景组合章节和指标。
- 不同岗位需要不同分析视角，但又不能各自维护一套规则。

### 商业价值

```text
标准化初筛 + 动态场景组合 + 可追溯证据 + 模块化报告
```

可量化的价值指标：

- 单个企业初筛时间下降比例。
- 每百家企业人工核查工作量下降比例。
- 风险信号发现率和误报率。
- 报告生成时间、人工修改时间和章节复用率。
- 用户周活、会话转报告率、报告导出率和续费率。

### 商业模式

- SaaS 订阅：按账号、企业数量或分析次数收费。
- 报告服务：按报告份数或章节组合收费。
- API 服务：向银行、园区、财税机构提供风险评分和解释接口。
- 私有化部署：面向对数据安全要求高的机构。
- 知识库和指标配置服务：提供行业化阈值、章节模板和方法论维护。

### 核心壁垒

不是“接了一个大模型”，而是四层可积累资产：

1. 真实财税数据与指标口径。
2. 可版本化的阈值、场景和方法论知识。
3. 类型安全的动态工具组合引擎。
4. Claim 驱动的可追溯报告与审计链。

大模型负责理解和表达，确定性系统负责数字和风险事实。这个边界既让系统可信，也能形成后续持续积累的数据和知识壁垒。

### 参赛展示主线

1. 用户用自然语言提出分析需求。
2. 系统识别主体、场景和分析目标。
3. 展示候选指标召回和动态组合过程。
4. 执行确定性工具并展示可追溯图表。
5. 生成多章节组合报告，并允许调整章节。
6. 展示同一问题在不同范围和场景下的可解释差异。

### 路演时需要避免的表述

- 不宣称替代税务、司法或审计结论。
- 不宣称所有企业风险都能自动判断。
- 不宣称模型可以自由生成财务数字。
- 不把 LangGraph、LangChain 或某个模型本身当作核心卖点。
- 不隐藏数据缺口和 unsupported 指标，真实边界比夸张能力更能建立可信度。
