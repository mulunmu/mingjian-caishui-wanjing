# 金融预测方向与公开数据可行性调研

日期：2026-09-17

## 一、结论先行

如果系统只做查询、汇总和简单解释，它更接近 BI 工具，不足以称为金融智能体。

真正有金融价值的能力分为四层：

```text
描述：发生了什么
诊断：为什么发生
预测：接下来可能发生什么
决策：应该采取什么行动
```

预测不一定要求深度神经网络。对金融风险场景，很多时候更合适的是：

- 逻辑回归 + 可解释特征。
- 梯度提升树（XGBoost / LightGBM）。
- 生存分析和违约时间模型。
- 时间序列和情景模拟。
- 异常检测与图关系模型。

但预测不能脱离数据和标签。没有可靠标签、时间对齐和回测，所谓预测只是演示。

## 二、不要先做什么

不建议把“股价涨跌预测”作为第一目标。

原因：

- 市场噪声极高。
- 价格已经包含大量公开信息。
- 短期收益预测容易过拟合。
- 很难给出稳定、可解释、可复现的业务价值。

更适合作为第一阶段的预测目标：

- 财务困境概率。
- 信用评级下调概率。
- 退市/特别处理风险。
- 盈利大幅低于预期概率。
- 现金流恶化概率。
- 行业风险周期和波动概率。
- 税务/合规异常概率。

这些目标更容易定义标签、回测和解释。

## 三、上市公司/行业风险方向需要预测吗？

需要，但不是一开始就需要复杂模型。

建议按成熟度推进：

```text
阶段 1：财务健康和行业比较
阶段 2：异常检测和风险归因
阶段 3：财务困境/评级下调概率
阶段 4：行业情景模拟和决策建议
```

如果没有预测层，这个方向只能作为金融分析工具；有了经过校准和解释的风险概率模型，才具备金融智能体价值。

## 四、公开数据源实际可达性验证

本次使用公开网络请求做了状态验证，结果如下：

| 数据源 | 验证结果 | 适用数据 | 备注 |
|---|---:|---|---|
| SEC EDGAR submissions | HTTP 200 JSON | 美国上市公司申报索引 | 公开、结构化、适合自动获取 |
| SEC companyfacts | HTTP 200 JSON | XBRL 财务事实 | 适合标准化财务指标 |
| World Bank API | HTTP 200 JSON | 宏观和国别指标 | 开放 API |
| FRED CSV | HTTP 200 CSV | 美国及全球宏观时间序列 | 适合时间序列特征 |
| Yahoo Finance chart | HTTP 403 | 行情 | 当前不稳定，不建议作为核心依赖 |
| Stooq CSV | HTTP 200 | 公开行情 | 需核对使用条款和字段质量 |
| CNINFO 首页 | HTTP 200 HTML | 中国上市公司公告 | 公开页面，自动采集需控制频率和合规 |
| SSE 首页 | HTTP 200 HTML | 上海市场公开信息 | 适合公告和研究，不等于完整 API |
| Tushare 文档 | HTTP 200 | 中国金融数据接口 | 通常需要 token 和积分/权限 |
| AKShare 文档 | HTTP 200 | 多来源公开数据聚合 | 便利但不能替代官方源和授权确认 |

结论：

```text
上市公司/行业风险方向的数据是可获取的，
但必须采用“官方源优先 + API 优先 + 爬虫补充”的组合。
```

## 五、建议的数据源优先级

### 第一优先级：官方公开源

- SEC EDGAR API
- 交易所和监管机构公开信息
- 公司年度报告和公告
- 官方统计和宏观数据库

### 第二优先级：开放 API

- FRED
- World Bank
- 其它有明确授权和数据说明的 API

### 第三优先级：便利型工具

- Tushare
- AKShare
- Stooq

这些工具适合快速开发和数据探索，但正式产品必须确认使用授权、更新稳定性和字段口径。

### 第四优先级：网页爬虫

仅采集公开、允许访问的页面，必须：

- 遵守 robots 和服务条款。
- 限制请求频率。
- 保留来源 URL 和采集时间。
- 做缓存、去重和增量更新。
- 不绕过付费墙、验证码和访问控制。

## 六、公开数据域可行性比较

| 方向 | 数据可得性 | 预测可行性 | 商业价值 | 迁移距离 |
|---|---:|---:|---:|---:|
| 上市公司财务风险 | 高 | 高 | 高 | 近 |
| 行业周期与风险 | 高 | 中高 | 高 | 近 |
| 公共采购/招投标风险 | 中 | 中 | 中高 | 中 |
| 供应链与供应商风险 | 中低 | 中高 | 高 | 中远 |
| 制造业质量/设备风险 | 低 | 高 | 高 | 远 |
| 医疗运营风险 | 低 | 高 | 高 | 远 |
| 教育质量分析 | 中 | 中 | 中 | 远 |
| 开源软件/供应链风险 | 高 | 中高 | 中 | 远 |
| 宏观经济分析 | 高 | 中 | 中 | 中 |

这里“数据可得性”是个人研究者视角，不是大型机构视角。

## 七、机器学习的正确位置

ML 不应该直接替代现有 Claim 和规则，而应该作为新的分析模块：

```text
Data Layer
-> Feature Layer
-> Prediction Module
-> Explanation Module
-> Claim
-> Conversation / Report
```

模型输出不是结论本身，而是：

```text
风险概率
置信区间
重要特征
模型版本
训练数据时间窗
适用边界
```

最终仍然要进入 Claim 和可视化层。

## 八、建议的模型组合

### 财务困境分类

- Logistic Regression：可解释基线。
- XGBoost / LightGBM：处理非线性和缺失。
- 概率校准：避免分数只是伪概率。
- SHAP：解释特征贡献。

### 评级下调/负面事件

- 生存分析：Cox 模型。
- 时序分类：滚动窗口和事件标签。
- 行业固定效应：避免行业差异被误判。

### 行业风险预测

- 时间序列：ARIMA、状态空间、Prophet 或梯度提升回归。
- 宏观变量：利率、通胀、PMI、行业产出。
- 情景模拟：基准/乐观/悲观三情景。

### 异常和舞弊

- Isolation Forest。
- Local Outlier Factor。
- 规则 + 分布偏移 + 图关系模型。

## 九、预测系统的验收标准

预测模型不能只看准确率。

必须报告：

- AUC / PR-AUC。
- Brier Score 或概率校准曲线。
- 召回率和误报率。
- 按时间切分的回测。
- 不同行业和年份的稳健性。
- 数据漂移和模型衰减。
- 特征贡献和可解释性。
- 训练时间、预测延迟和成本。
- 数据泄漏检查。

尤其是金融数据，必须用时间切分，不能用随机切分。

## 十、建议的首个迁移方向

我建议第一迁移方向确定为：

```text
公开上市公司财务健康、财务困境与行业风险分析
```

原因：

1. 与当前财税分析最接近。
2. 公开数据可获得，官方源和 API 都可验证。
3. 可以同时支持描述、诊断、预测和情景分析。
4. 能产出高价值报告，而不是单纯行情查询。
5. 后续可以扩展到供应链、行业和宏观数据。

## 十一、产品定位

不应定位为：

```text
财经数据查询机器人
```

应定位为：

```text
面向金融风险的可解释预测与决策分析引擎
```

核心能力：

- 数据分析。
- 风险诊断。
- 概率预测。
- 情景模拟。
- 证据链和报告。
- 长记忆和跨话题追问。

## 十二、后续顺序

1. 当前财税系统闭环。
2. 财税 Domain Pack 封装。
3. Core Engine、Case、Claim、Visual、Report 接口冻结。
4. 上市公司 Domain Pack 最小数据接入。
5. 先做描述/诊断，再做风险概率模型。
6. 建立时间切分、回测、校准和漂移监控。
7. 通过同一引擎复用到第二个公开数据域。
8. 最后再接入语音和移动端。

## 十三、最终判断

预测是金融系统从“工具”走向“智能体”的必要条件，但预测的对象应是风险概率、财务状况和决策情景，而不是一开始就做股价涨跌。

上市公司/行业风险方向的数据是可获取的，适合作为第一个迁移域。真正决定产品价值的不是模型有多深，而是：

```text
数据是否可持续
标签是否可靠
预测是否校准
结论是否可解释
结果是否可追溯
报告是否能进入决策
```

这也是后续从财税数据跳向公开金融数据和更大分析平台时，最应该坚持的底线。
