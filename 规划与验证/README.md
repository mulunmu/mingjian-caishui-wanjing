# 规划与验证

本目录独立保存当前财税项目闭环之后的演进规划、方向调研和数据链路验证，不混入阶段验收报告。

## 当前结论

1. 当前财税数据项目先完成现有系统闭环，不在同一版本并行接入第二领域正式数据。
2. 下一方向优先选择“公开上市公司财务健康、财务困境与行业风险分析”。
3. 数据采集是迁移的第一道门槛，优先级高于预测模型和复杂 Agent。
4. 公开数据链路采用“官方源优先、API 优先、爬虫补充、授权确认、证据可追溯”的原则。
5. 财报先形成结构化财务事实，再抽取披露事件；舆情必须事件优先、情绪后置。
6. 预测目标优先选择财务困境、评级下调、现金流恶化和行业风险概率，不先做股价涨跌。
7. 已有确定性引擎应通过 Domain Pack、Tool Registry、Claim、RAG 和 Report Block 接口复用，不重写核心。

## 与当前系统的关系

本目录中的内容属于后续版本输入，不改变当前财税主链的已验收行为。只有在数据契约、解析准确率、字段校验和回测标准通过后，才允许接入新的生产 Domain Pack。

可复用出口：

- 数据事实 -> `Claim` 和证据链。
- 指标与阈值 -> Tool Registry / RAG。
- 事件与章节 -> Report Block。
- 预测结果 -> 独立的概率 Claim 和可解释报告模块。
