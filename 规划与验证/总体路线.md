# 总体路线

日期：2026-09-18

## 一、产品定位

目标不是做成“财经数据查询机器人”，而是形成：

```text
面向金融风险的可解释分析、预测与决策报告引擎
```

系统能力分为四层：

```text
描述：发生了什么
诊断：为什么发生
预测：接下来可能发生什么
决策：应该采取什么行动
```

## 二、迁移原则

1. 先完成当前财税数据闭环，再启动第二领域正式 ETL。
2. 先解决数据采集和标签质量，再谈预测模型。
3. 当前确定性内核保持不变，新领域通过 Domain Pack 接入。
4. 所有数字、事件和预测结果必须进入 Claim 和证据链。
5. 官方源和结构化 API 优先，网页爬虫只做合法补充。
6. 不以股价涨跌预测作为第一阶段目标。

## 三、阶段路线

### 阶段 A：财税系统冻结

- 冻结 SemanticPlan、LangGraph、异步 DAG、Claim、RAG 和 Report Block 契约。
- 完成现有财税数据的全量验证、回滚和发布。

### 阶段 B：公开数据采集试点

- 选定一个交易所和一小组上市公司。
- 抽取 3 年年度、半年度、季度报告和核心风险公告。
- 建立文件、字段、表格和事件的证据位置。
- 通过数据采集验收后，才进入下一阶段。

### 阶段 C：上市公司 Domain Pack

- 映射财务报表、风险事件、行业基准和公司画像。
- 建立描述和诊断型指标。
- 复用现有对话、RAG、可视化与报告组装。

### 阶段 D：预测与回测

- 先做可解释基线：Logistic Regression。
- 再做非线性模型：XGBoost / LightGBM。
- 增加概率校准、SHAP、时间切分和数据漂移监控。

### 阶段 E：行业与情景模拟

- 行业周期、宏观变量和多情景推演。
- 风险概率、敏感性分析和决策建议。

### 阶段 F：语音与移动端

- 在数据、分析、报告和预测稳定后，再接入语音与手机系统能力。

## 四、Domain Pack 接口

新领域最终必须只替换领域内容，不复制主引擎：

```text
Domain Pack
  -> 数据源与采集器
  -> 字段与指标口径
  -> 维度与阈值
  -> 分析模式
  -> 风险事件标签
  -> 报告章节与 Block
```

主引擎继续负责：

```text
SemanticPlan -> Tool Composition -> Async DAG -> Claim -> RAG -> Report Block
```

## 五、首个迁移域

首选：

```text
公开上市公司财务健康、财务困境与行业风险分析
```

选择原因：

- 与当前财税风险分析距离最近。
- 公开数据源可达性较高。
- 可同时支持描述、诊断、预测和情景分析。
- 可产出高价值报告，而不是简单行情查询。
- 数据采集与字段口径验证成功后，可继续扩展到供应链和宏观领域。
