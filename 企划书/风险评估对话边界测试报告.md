## 一、项目概述

### 1.1 系统架构

明鉴01 是一个前后端合并的税务风险研判系统：

- **前端**: React + TypeScript (Vite)，使用 Zustand 状态管理，Axios HTTP 客户端
- **后端**: FastAPI (Python)，异步 SQLAlchemy，PostgreSQL 持久化

### 1.2 风险评估对话实现机制

**请求链路**:

```
用户输入 → ChatInput.tsx → ResearchCenter.handleSend()
  → chatStore.sendMessage(text)
    → chatApi.send({query, session_id})
      → POST /api/v1/chat
        → chat_router.route_chat()
          → intent_engine.recognize()        # 正则意图识别
          → llm_semantic_parser (可选)       # LLM 语义解析
          → semantic_query.correct/merge     # 语义查询校正
          → judgment_service.run_*()         # 研判切片（纯算法，数字不经过 LLM）
          → llm_reply.generate_claim_reply() # LLM 润色回复（带幻觉防护）
        ← {reply, data:{claims, followups}, session_id, charts, ...}
      ← ChatResponse{conclusion, evidence, followups, chart, trace}
    ← Message{content, followups, evidence, chart}
  → AIMessage / ConclusionCard 渲染
```

**关键设计模式**:
- **数字来源**: 所有数字由 `judgment_service` 从数据库计算产出（Claim 对象），LLM 仅负责改写措辞
- **幻觉防护**: `hallucination_guard` 过滤 LLM 输出中未锚定的数字
- **会话记忆**: 内存 L1 + PostgreSQL L2，30 分钟活跃 TTL
- **降级策略**: LLM 不可用时自动降级到规则模板回复

## 三、潜在 Bug 清单

按严重程度排序：

### 🔴 高严重度

#### BUG-01: 前端图表数据字段映射错误导致图表永远不显示

- **问题描述**: 后端返回的图表数据位于 `res.charts`（顶层字段），但前端 `chatApi.send()` 中 `chart` 字段硬编码为 `undefined`，从未读取后端的 `charts` 数据。
- **触发条件**: 所有返回图表的查询（趋势、评分、基准、舞弊、信号等）
- **影响范围**: 所有对话中的图表功能完全不可用
- **代码位置**:
  - 后端 `chat_router.py:412` 返回 `{"charts": charts, ...}`
  - 前端 `src/api/chat.ts:105` 硬编码 `chart: undefined`
- **严重程度**: 🔴 高
- **建议修复方向**: 在 `chatApi.send()` 中读取 `res.charts` 并转换为前端 `ChartConfig` 格式，例如：
  ```typescript
  chart: res.charts ? (res.charts as ChatResponse['chart']) : undefined,
  ```

#### BUG-02: 错误回退消息暴露技术细节并回显用户输入

- **问题描述**: 当后端请求失败时，`chatStore.sendMessage` 的 catch 块生成的消息包含用户原始输入文本和技术实现细节。
- **触发条件**: 后端不可用、网络错误、超时等任何异常
- **影响范围**: 所有错误场景下的用户体验
- **代码位置**: `src/stores/chatStore.ts:96-107`
  ```typescript
  content: `收到你的问题："${text}"。后端服务尚未就绪，当前为演示模式。请启动后端 API 后重试。`
  ```
- **严重程度**: 🔴 高
- **问题影响**:
  1. 用户输入的敏感信息可能通过错误消息泄露（如粘贴的内部数据）
  2. "后端服务尚未就绪"暴露系统架构细节
  3. "演示模式"暗示系统不可用，降低用户信任
- **建议修复方向**: 使用通用错误提示，不回显用户输入："抱歉，服务暂时不可用，请稍后重试。"

### 🟡 中严重度

#### BUG-03: 前端不区分错误类型，统一显示演示模式消息

- **问题描述**: 所有 HTTP 错误（429 限流、503 服务不可用、500 内部错误、网络超时）都走同一个 catch 块，显示相同的演示模式消息。
- **触发条件**: 任何非 200 响应
- **影响范围**: 用户无法了解错误原因，无法采取正确的恢复措施
- **代码位置**: `src/stores/chatStore.ts:94-107`
- **严重程度**: 🟡 中
- **建议修复方向**: 根据 HTTP 状态码显示不同提示：
  - 429: "请求过于频繁，请稍后再试"
  - 503: "服务暂时不可用，请稍后重试"
  - 超时: "请求超时，请检查网络后重试"
  - 其他: "发生未知错误，请稍后重试"

#### BUG-04: 超长输入无前端校验

- **问题描述**: 前端 `ChatInput` 组件无 `maxLength` 限制，用户可以输入任意长度的文本。后端也未对 `query` 字段做长度校验。
- **触发条件**: 用户粘贴大段文本或持续输入
- **影响范围**:
  1. LLM 处理超长输入可能超时（40 秒 `litellm` timeout）
  2. 请求体过大可能影响后端性能
  3. 前端 textarea `maxHeight: 120` 限制了显示但不限制数据
- **严重程度**: 🟡 中
- **建议修复方向**: 前端添加 `maxLength={2000}` 限制，后端 `ChatRequest.query` 添加 `max_length` 约束

#### BUG-05: 英文输入无法触发任何功能

- **问题描述**: `intent_engine` 的所有正则模式都使用中文关键词，英文输入（如 "What is the risk score?"）无法匹配任何功能，始终走 general 路径。
- **触发条件**: 用户使用英文提问
- **影响范围**: 国际化场景下的可用性
- **代码位置**: `backend/app/services/intent_engine.py:45-61`
- **严重程度**: 🟡 中
- **建议修复方向**: 在 `_FUNC_PATTERNS` 和 `_DIM_PATTERNS` 中添加英文别名，或在 `llm_semantic_parser` 中处理英文输入

#### BUG-06: 120 秒超时设置过长

- **问题描述**: 前端 axios 超时设置为 120 秒，后端 LLM 调用超时为 40 秒。用户在网络中断时需等待 2 分钟才能看到错误提示。
- **触发条件**: 网络中断或后端无响应
- **影响范围**: 用户体验
- **代码位置**: `src/api/client.ts:4` `timeout: 120000`
- **严重程度**: 🟡 中
- **建议修复方向**: 将前端超时降低到 30-45 秒，与后端 LLM 超时对齐

### 🟢 低严重度

#### BUG-07: Welcome 消息时间戳在模块加载时固定

- **问题描述**: `welcomeMessage.timestamp = Date.now()` 在模块首次加载时执行，而非消息实际显示时。如果用户长时间保持页面打开，欢迎消息的时间戳会与实际显示时间有偏差。
- **触发条件**: 页面长时间保持打开
- **影响范围**: 仅影响欢迎消息的时间显示
- **代码位置**: `src/stores/chatStore.ts:35`
- **严重程度**: 🟢 低
- **建议修复方向**: 将 `timestamp` 设为响应式值，或在 `clearChat` 时重新生成

#### BUG-08: "电子信息" 行业关键词匹配可能不精确

- **问题描述**: `_match_industry` 使用子串匹配，"电子信息行业" 中的 "信息" 会匹配到 "IT软件"。但 "电子信息" 通常属于制造业下的子类，而非 IT 软件。
- **触发条件**: 用户输入包含 "信息" 但意指制造业
- **影响范围**: 行业分类精度
- **代码位置**: `backend/app/services/intent_engine.py:32` `("信息", "IT软件")`
- **严重程度**: 🟢 低
- **建议修复方向**: 添加更精确的行业关键词映射，或使用 LLM 语义解析作为优先路径

#### BUG-09: 前端 ChatPanel 双重 sendMessage 调用路径

- **问题描述**: `ChatPanel` 组件同时支持内部 `sendMessage`（来自 chatStore）和外部 `onSend` prop。`ResearchCenter` 传入 `onSend={handleSend}`，其中 `handleSend` 调用 `sendMessage`。这导致了两层间接调用，且 `ChatPanel` 内部的 `sendMessage` 永远不会被使用。
- **触发条件**: 正常使用（设计问题）
- **影响范围**: 代码可维护性，不影响功能
- **代码位置**: `src/components/chat/ChatPanel.tsx:18-21`
- **严重程度**: 🟢 低
