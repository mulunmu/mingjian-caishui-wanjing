# 业务规则手册 · 报告校验（唯一依据）

> 口径变更必须先改本手册与中心化字典（`financial_benchmarks.FINANCIAL_RATIOS` / `scope_contract`），再改代码或提示词。禁止绕过文档直接改模板硬编码阈值。

---

## 0. 四层防护职责

| 层 | 模块 | 职责 | 禁止事项 |
|---|---|---|---|
| L1 真相源 | `FINANCIAL_RATIOS`、`scope_contract`、本手册 | 阈值、特殊会计、聚合统计口径 | 模板/提示词写死数字 |
| L2 规则引擎预校验 | `report_preflight.run_preflight` | PDF 生成前拦截 | 把判定甩给 LLM |
| L3 LLM | `llm_reply` 等 | 仅润色已算好的片段 | 计算、重判定、统计计数 |
| L4 后置校验 | `run_postflight_html` + `.validation.json` | HTML/数字/禁词兜底 | 用人眼代替机器 |

铁律：**错误报告不得生成**。预校验或后置校验失败 → 抛错拒出 PDF。

## 1. 单主体边界

| 规则 ID | 条件 | 强制结果 |
|---|---|---|
| E-EQ-01 | 所有者权益 < 0 | ROE 等权益分母指标 → `计算失效`；禁止进主要优势 / 同业对标；数值格展示「—」 |
| E-EQ-02 | 负债类金额 < 0 或不可能比率 | → `账务异常`；不得当普通达标 |
| E-ADV-01 | 营收/净利润同比 | **不进主要优势**（未跌破预警线 ≠ 经营亮点） |
| E-GRO-01 | 净利润同比 < -20% | 评级「预警」（与营收同比同口径） |
| E-SUM-01 | 首页优势/风险/建议 | 完整输出，禁止 `text[:N]` 中间截断；空条拒出 |
| E-TMP-01 | `period_count < 2` | 禁止「持续 / 逐年 / 不断」（「持续经营」除外） |
| E-RAD-01 | 雷达维度 | 必须 ⊆ 六维正文章节；多余维度拒出 |
| E-MISS-01 | 无现金流量表等 | 统一【暂无可用数据】，不编造 |

阈值一律引用 `FINANCIAL_RATIOS[*].warn_threshold`（如资产负债率 0.7），禁止模板写死「70%」作为判定源（展示文案可格式化自字典）。

## 2. 聚合边界

| 规则 ID | 条件 | 强制结果 |
|---|---|---|
| A-CNT-01 | 任意「N 家」风险主体计数 | **N ≤ 当前子集 sample_count**；越界拒出 |
| A-CNT-02 | 拖累因素 | 按**主体去重**计数（跨维度同 item 只计 1 家） |
| A-CNT-03 | 摘要风险计数展示 | 统一 `{标签} {n} 家 / 样本 {N} 家`（税务/舞弊/信号/评分同源） |
| A-SMP-01 | `N < SMALL_SAMPLE_N(30)` | 封面/摘要必须出现小样本「仅供参考」提示 |
| A-FLD-01 | 聚合报告 | 禁止「风险等级 / 评级展望」单主体字段；禁止「[据推断]」 |
| A-SCP-01 | 有行业/地区/企业筛选 | 锁定章节 `sample_count == scope_n`；会话缓存不得喂全集 |

## 4. 机器闸门与日志

1. **预校验硬门禁**（拒出 PDF）：范围对齐、风险计数≤N、禁词/字段隔离、雷达⊆章节、权益失效禁入优势、摘要空条、单期时序词、聚合禁「据推断」、小样本提示缺失、无可溯源正文  
2. **预校验软告警**（写入日志、暂不拒出）：章节数字未锚定、风险措辞与 clean 章矛盾 —— 逐步收紧  
3. **后置（WeasyPrint）**：HTML 禁词/字段隔离/时序硬拒；数字孤儿记 warning  
4. **后置（FPDF 降级）**：`run_postflight_context` 表面禁词/时序硬拒，**禁止跳过兜底**  
5. **日志**：`reports/{report_id}.validation.json`  
6. **小样本**：`N < SMALL_SAMPLE_N(30)` 已生产启用（封面 banner + 预校验硬拦缺失）

发布门禁：`pytest tests/test_report_guardrails_closed_loop.py tests/test_p0_report_mechanisms.py` 必须全绿。

## 5. 变更流程

1. 改本手册对应规则 ID  
2. 改字典 / `scope_contract` / `report_preflight`  
3. 补或改自动化用例（边界优先）  
4. `docker compose up -d --build backend`  
5. 跑上述 pytest + 可选 `_spec_audit_reports.py`  
6. 再人工抽 PDF（仅作体验，不作为正确性唯一依据）
