# 明鉴01 · 报告设计规范 v1

> 核心理念：**同一批数据，理解不同场景的语义，生成不同语气的报告。**
> 数据是唯一的事实源，场景决定"数据意味着什么"（语义），语义决定"怎么对读者说"（语气），版式让这一切被专业地呈现。
> 定位：**报告是产品本体（不是输出功能），是「定制用户」的买单理由。** 报告要交付的是"可行动的研判结论"，不是数据罗列。

---

## 0. 一句话定义

- 一套数据 → 一份事实（确定性计算，永远不变）
- 一个场景 → 一层语义（哪些指标进报告、权重多大、解读口径是什么）
- 一种语气 → 一种表达（立场、结论强度、风险措辞、行动导向）
- 一份版式 → 一种信任信号（评级机构/审计级专业排版）

---

## 1. 五层架构

| 层 | 名称 | 职责 | 谁决定 | 可否被场景改变 |
|---|---|---|---|---|
| L0 | 数据层 | 193 家主体的工商/税务/发票/财务/司法原始数据 + 指标计算 | 确定性计算 | ❌ 不可变 |
| L1 | 指标语义层 | 场景选择指标、定权重、定解读口径、定客观评级 | 场景配置 | ✅ 选择/权重/解读变，**评级不变** |
| L2 | 语气层 | 立场、结论强度、风险措辞、行动导向 | 场景配置 | ✅ 可完全重写 |
| L3 | 结构层 | 场景 × 模块 → 章节装配顺序 | 场景配置 | ✅ |
| L4 | 版式层 | 字体/字号/配色/网格/编号 | 全局规范 | ⚠️ 全局统一，场景仅微调强调色 |

---

## 2. 铁律（一致性 + 抗幻觉，最高优先级）

1. **数字只来自 L0**：任何指标值、金额、百分比只由计算层产出，LLM 仅组织语言，不得生成、改写、估算任何数字。
2. **客观评级由 L1 统一决定，与场景无关**：资产负债率 78% 的客观结论永远是"预警（超过 70% 警戒线）"；语气层只改"如何措辞"和"给什么建议"，**不得把一个场景说成健康、另一个说成高危**。
3. **语气只改表达，不改事实**：立场/建议/排序可变，事实与评级不可变。
4. **弃权优先于编造**：无数据 → 明确写"该项无数据/未覆盖"，不得推测填值。
5. **每条结论可溯源**：正文每条风险判断都带来源（指标名 + 原始表字段 + 值）。

> 例（同一事实，三种语气）：
> - 授信报告：「资产负债率 78%，超过 70% 警戒线，偿债压力偏大，建议审慎控制授信额度。」
> - 尽调报告：「资产负债率 78%，杠杆偏高，需进一步核实偿债安排及再融资能力。」
> - 自检报告：「资产负债率 78%，高于行业均值 62%，建议通过压降有息负债优化资本结构。」
> 三个句子，同一个客观评级「预警」、同一个数字「78%」。

## 3. 场景矩阵（场景 → 语义关注 → 语气 → 默认模块）

| # | 场景 | 读者 | 决策 | 语义关注（高权重指标） | 语气基调 | 默认模块 |
|---|---|---|---|---|---|---|
| S1 | 综合授信 | 银行/金融机构 | 是否授信、额度 | 偿债、现金流、关联担保、诉讼 | 审慎、结论明确、给额度建议 | 综合 + 财务 + 司法 |
| S2 | 投资尽调 | 投资方 | 是否投资 | 成长性、盈利质量、股权、合规 | 客观中性、摆证据、列风险点 | 综合 + 财务 + 工商 |
| S3 | 供应商/客户准入 | 采购/销售 | 是否合作、账期 | 付款能力、经营连续性、诉讼 | 合作导向、信用分级 | 综合 + 发票 + 司法 |
| S4 | 税务合规 | 企业/中介/监管 | 涉税自查/整改 | 税负率、申报、虚开信号 | 合规陈述、风险分级、整改建议 | 税务 + 发票 |
| S5 | 内部自检 | 企业高管 | 经营改进 | 全维度对标行业 | 建设性、改进导向 | 综合（四模块全开） |
| S6 | 反欺诈/虚开专项 | 风控/监管 | 立案/预警 | 循环开票、红冲作废、品目异常 | 证据导向、预警分级 | 发票 + 税务 |

## 4. 语气规范（L2 四要素）

语气 = **立场 + 结论强度 + 风险措辞 + 行动导向** 四要素的组合，每个场景固定一套。

| 场景 | 立场 | 结论强度 | 风险措辞库 | 行动导向 | 免责声明 |
|---|---|---|---|---|---|
| S1 授信 | 银行 | 明确（给额度/期限建议） | 偏高/压力/需关注/审慎 | 建议授信额度、担保要求 | 「仅供授信决策参考，不构成授信承诺」 |
| S2 尽调 | 投资方 | 中性（不下结论） | 存在/需进一步核实/供参考 | 尽调核查清单 | 「不构成投资建议」 |
| S3 准入 | 采购方 | 分级（建议合作/审慎/不建议） | 稳定/脆弱/集中度 | 建议账期、额度、担保 | 「仅供合作评估参考」 |
| S4 税务 | 合规方 | 分级（高/中/低风险） | 异常/待整改/涉嫌 | 整改项 + 法规条款引用 | 「依据现行税法，具体以主管税务机关认定为准」 |
| S5 自检 | 企业 | 建设性（亮点+改进） | 可优化/建议关注/亮点 | 对标行业改进方向 | 「内部管理参考」 |
| S6 反欺诈 | 风控 | 证据导向（疑似/高度疑似） | 循环开票/红冲异常/品目不符 | 预警等级 + 证据清单 | 「线索提示，需人工复核」 |

**措辞硬性规则**：
- 禁止模糊副词滥用（"可能/大概/或许"），不确定的判断必须标注"**据推断**"（inferred）并给依据。
- 计算得到的判断标注"**据计算**"（computed），人工/规则断言标注"**据规则**"（asserted）。
- 每个风险点固定句式：`现象（数字）→ 对照（阈值/行业）→ 结论（评级）→ 建议（场景化）`。

## 5. 报告结构（L3）

### 5.1 通用骨架（所有报告共有）

1. **封面**：报告类型 + 主体名（按脱敏开关）+ 报告期 + 生成日期 + 评级级别 + 评级展望 + 编制方
2. **核心结论前置页**：评级 + 主要优势（≤3 条）+ 主要风险（≤3 条）+ KPI 大数字卡
3. **正文**（场景 × 模块装配）
4. **附录**：指标溯源表 + 数据来源 + 计算公式 + 免责声明

### 5.2 四大模块章节清单

| 模块 | 章节 | 核心指标（值 → 阈值对照） |
|---|---|---|
| **综合** | 企业画像 / 综合评分雷达 / 同业分布 Top X% / 工商 / 司法 / 违法处罚 | 评分、评级、执行金额、处罚次数 |
| **财务** | 盈利能力 / 偿债能力 / 营运能力 / 成长能力 / 三大报表 / 杜邦分解 | 净利率>5%、毛利率>20%、资产负债率<70%、流动比率>1.5、速动比率>1 |
| **税务** | 涉税总览 / 增值税(税负率) / 所得税(贡献率) / 申报缴纳 / 税务风险点 | 增值税税负率 vs 行业×0.6、欠税、滞纳金 |
| **发票** | 开票概览 / 销项(TOP10客户) / 进项(TOP10供应商) / 上下游关联 / 异常信号 | 客户/供应商集中度>50%、红冲作废>10%、顶格开具>50% |

## 6. 版式规范（L4，全局统一）

### 6.1 字体
- 标题：**衬线**（思源宋体 / Noto Serif SC）
- 正文：**无衬线**（思源黑体 / Inter / 苹方）
- 财务数字：启用 `font-feature-settings: "tnum"`（等宽数字，表格对齐）

### 6.2 字号 / 行距
- H1 报告题 2.25rem/700 · H2 章 1.5rem · H3 节 1.15rem · 正文 ≥10.5pt（印刷下限）· KPI 大数字 ~2rem · 脚注 0.8rem
- 正文行高 1.75，段落最大宽 ~720px

### 6.3 配色（克制，满足 WCAG 2.0 对比度）
- 主色 深蓝 `#1e3a8a`（财务稳定/品牌）
- 达标 绿 `#059669` / 预警 琥珀 `#d97706` / 高危 红 `#dc2626`
- 背景 暖白 `#fafaf8`，正文 石板灰 `#334155`
- **规则**：冷色用于数据/稳定，暖色（琥珀/红）只用于风险预警，禁止高饱和大色块

### 6.4 布局 / 图表 / 溯源
- 模块化网格 + 充足留白；**结论前置**，正文递进：基础数据 → 指标计算 → 趋势 → 风险预测
- 图表紧随文字 + 连续编号（"图 1-1"）+ 图注在图下方；关键指标加粗/色块 + 趋势图 + 对比表
- 多级目录 + 交叉引用脚注（"见 3.2.1"）；数据来源注释 + 附录原始数据
- 页眉含报告编号/版本，页脚含页码 + 保密级别

## 7. 抗幻觉 / 输出边界约束

1. 数字只走计算层（L0）；LLM 输入只含"已计算的指标 + 阈值 + 评级"，不含可编造的空。
2. 结构化解码：LLM 输出被约束为 `结论 + 依据(引用指标) + 建议`，逐条校验引用的指标确实存在且值一致。
3. 幻觉守卫（沿用现有 hallucination_guard）：叙述中出现的数字必须与 L0 某指标完全一致，否则拒收。
4. 空报告门禁（沿用）：主体无数据 → 直接报"无数据/未覆盖"，不生成正文。
5. 脱敏开关：封面/正文是否显示真实企业名与信用代码，由 `config.anonymous` 决定，不影响数据与评级。

## 8. 报告价值内核与生成模式（报告 = 产品本体）

> 报告不是"输出功能"，而是产品本体，是 VIP 的买单理由。自动、定制、主动监测三者都围绕"给客户交付可行动的研判结论"。

### 8.1 价值三要素（每份报告都必须具备）

1. **研判结论（不是数据罗列）**：开头即"核心研判"——评级 + 主要优势（≤3）+ 主要风险（≤3）+ 一句话总评。风险必须是"洞察"，由多指标联动推导，不是单指标罗列。
   - 例：营收 +12.9% 但经营现金流 -7,483 万、应收周转天数 45→89 天、前三大客户集中度 68% → 研判"**纸面盈利、现金空心**，回款风险上升"。
2. **可行动建议（场景化）**：每个洞察必带一个可执行动作（授信→额度/担保、税务→整改项、自检→改进方向）。
3. **主动监测 + 差异驱动**：数据刷新后做差异检测，只在"有变化"时更新，并高亮"较上期变化"。

### 8.2 三种生成模式（同一引擎，价值导向）

- **自动生成 = 主动研判**（不是定时批量渲染）：数据刷新 → 差异检测（新诉讼/开票异常/财务恶化）→ 触发生成 → 标题带差异化结论（如《XX企业风险异动提示·C级》）。
- **定制生成 = 报告向导**：选主体 → 选模块 → 设场景 → 深度/基准/阈值偏好 → 报告期 → 脱敏 → 格式 → 可存模板。
- **主动订阅 = 异动推送**：客户订阅企业 → 系统盯数据 → 出事自动出报告并推送。

### 8.3 订阅分层（定制用户 / 非定制用户）

> 术语：**定制用户**（订阅付费，全功能）/ **非定制用户**（未订阅，可预览不可下载）。

| 层级 | 内容 |
|---|---|
| 非定制用户 | 企业基础信息、单企业裸指标（无洞察）、行业趋势概览、**报告预览**（不可下载） |
| **定制用户** | ① 四模块专业研判报告（洞察+建议+溯源+评级）② 主动监测 + 异动订阅推送 ③ 6 场景定制 + 阈值/基准偏好 + 存模板 ④ 同业深度对比 ⑤ PDF/Word **下载** + 批量导出 + 脱敏开关 |

**权限边界（硬规则）**：
- **预览**：非定制用户可用（营销钩子——看到报告长啥样，但不给下载）
- **下载**：仅定制用户
- **生成 PDF**：仅定制用户（生成即产生可下载产物）

**UI 交互**：功能入口**全量露出、不隐藏**；非定制用户点击定制功能时弹窗提示"该功能为定制用户专享，请升级"，不做静默隐藏/404。

### 8.4 权限模型实现约定

- 数据模型：`AppUser` 增 `plan` 字段（内部枚举 `subscriber`=定制 / `free`=非定制，避免与"定制报告场景 custom"重名），与 `role`（`admin`/`user` 系统权限）解耦。
- 测试账号：`role=admin + plan=subscriber` → 全功能（admin 绕过 plan 检查 = 最高权限）。
- 注册账号：默认 `plan=free`（非定制）。
- 后端依赖 `require_plan("subscriber")` 守卫：**生成 / 下载 / 邮件 = subscriber**；**预览 = 放行**。
- 演示态兜底：`AUTH_REQUIRED=false` 未登录放行（等同定制，便于开发）。
- 前端：登录返回带 `plan`，按钮全量露出，点击定制功能时对非定制用户弹升级窗。
