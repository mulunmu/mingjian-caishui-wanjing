# 阶段 9I：旧入口退役最终闭环

日期：2026-09-17

## 结论

活动应用的旧对话入口已经退役，Stage 9 不再停留在“只把旧文件移走”的状态。

```text
active-app legacy imports=0
legacy marker count=0
retirement audit safe_to_retire=true
production image contains legacy package=no
semantic primary fail-closed=yes
```

`backend/legacy` 现在只保留为仓库历史归档，供尚未迁移完成的离线测试和脚本引用；
它不在生产镜像中，也不会被活动 API 导入或调用。若后续要删除整个目录，只需要先
迁移/清理这些离线引用，不再涉及生产运行链路。

## 已完成的真实改动

- 活动 `/api/v1/chat` 删除 legacy fallback 导入和调用。
- 语义主路径内部异常统一返回 503，不再偷偷切回旧路由。
- 活动 `app/` 中旧的意图正则、软降级关键词和 `route_chat` 标记全部清零。
- 固定报告和定制报告重新接入语义主路径，仍使用现有报告服务和确定性章节装配。
- `DialogAct` 对 LLM 输出的字符串 `null`、`None`、`undefined` 做 schema 入口归一，
  修复模型偶发输出 `refusal_kind="null"` 导致整轮分析失败的问题。
- `backend/legacy/` 加入生产 Docker 忽略清单，镜像中确认不存在该目录。
- 退役审计增加“活动应用不得导入 legacy 包”的独立阻断检查。

## 未删目录说明

当前没有直接执行 `rm -rf backend/legacy`，因为仓库中仍有针对旧路由的历史测试、
离线 smoke 脚本和图表/邮件辅助函数引用。删除它们不会改变生产运行结果，但会破坏
这些离线入口。正确顺序是：

1. 将仍需保留的离线验证脚本迁移到活动语义链路。
2. 删除只验证已退役实现的测试和脚本。
3. 删除 `backend/legacy`，再次运行全量回归与生产矩阵。

在此之前，生产容器已经通过 `.dockerignore` 和活动导入审计与旧包隔离。
