# 阶段 9I：旧入口物理删除最终闭环

日期：2026-09-17

## 结论

活动应用的旧对话入口及其目录已经物理删除，Stage 9 不再保留任何旧实现。

```text
active-app legacy imports=0
legacy marker count=0
retirement audit safe_to_retire=true
legacy package present=false
legacy package in production image=no
semantic primary fail-closed=yes
```

`backend/legacy` 已从仓库删除。活动代码、全量测试、离线脚本和生产镜像均不再
导入或包含该目录。

## 已完成的真实改动

- 活动 `/api/v1/chat` 删除 legacy fallback 导入和调用。
- 语义主路径内部异常统一返回 503，不再偷偷切回旧路由。
- 活动 `app/` 中旧的意图正则、软降级关键词和 `route_chat` 标记全部清零。
- 固定报告和定制报告重新接入语义主路径，仍使用现有报告服务和确定性章节装配。
- `DialogAct` 对 LLM 输出的字符串 `null`、`None`、`undefined` 做 schema 入口归一，
  修复模型偶发输出 `refusal_kind="null"` 导致整轮分析失败的问题。
- 固定报告命令增加确定性 `report` 分类，避免“生成评级报告”被模型偶发判成 FAQ。
- 删除 `backend/legacy/` 整个目录，包括 `chat_router.py` 和 `intent_engine.py`。
- 将仍有价值的意图词表测试迁移到 `app.services.semantic_lexicon`。
- 删除只验证已退役实现的测试、smoke 脚本和 shadow batch 脚本。
- 移除 `.dockerignore` 中不再需要的 `legacy/` 隔离项。
- 退役审计增加“活动应用不得导入 legacy 包”的独立阻断检查。
- 退役审计增加“`backend/legacy` 目录不得存在”的独立阻断检查。
