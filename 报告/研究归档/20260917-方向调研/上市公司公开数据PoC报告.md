# 上市公司公开数据 PoC 验证报告

日期：2026-09-17

## 一、验证目标

验证不依赖付费 API 的上市公司公开数据链路是否可运行：

```text
CNINFO 元数据查询
-> 年报 PDF 下载
-> PDF 文本和表格解析
-> 核心财务字段抽取
-> 风险事件候选抽取
-> 简单情绪基线
```

## 二、验证样本

```text
公司：贵州茅台
代码：600519
报告：贵州茅台 2024 年年度报告
```

```text
资产总计 >= 负债合计：true
```

## 四、事件候选抽取

PoC 已召回以下事件类别：

- 持续经营
- 减值
- 关联交易/关联方
- 担保
- 诉讼/仲裁
- 监管/处罚
- 违约
- 会计差错/前期差错更正
- 风险提示/重大风险

需要注意：

```text
关键词命中只代表“存在审核候选”，不代表风险已经成立。
```

例如：

- “持续经营”可能来自标准审计责任描述。
- “前期差错更正”可能只是表格空行标签。
- “风险提示”可能只是报告章节说明。

因此下一层必须加入适用性判断、上下文分类和规则/LLM 复核。

## 五、简单情绪基线

PoC 使用正负词典做了基线统计：

```text
正向词命中：165
负向词命中：297
简单分数：-0.2857
```

但这个结果不能直接作为风险结论。

原因是：

- 财报大量出现“风险、减值、诉讼”等专业名词。
- 这些词出现在制度说明、会计政策或空白表格中也可能被命中。
- 通用情感模型不了解披露语境。

验证结论：

```text
财报舆情必须事件优先，情绪后置。
```

## 六、已经验证可行的部分

- 公开公司列表获取。
- 年报元数据查询。
- 年报 PDF 下载。
- 文本层提取。
- 表格识别。
- 主财务字段抽取。
- 页码和原文片段溯源。
- 风险事件候选召回。
- JSON 报告输出。

## 七、还未解决的部分

- 跨页表格合并。
- 不同公司报表模板差异。
- 单位换算和亿元/万元识别。
- 负数和括号金额识别。
- 表格单元格语义分类。
- 事件适用性判断。
- OCR 扫描件处理。
- 多公司批量下载与断点续传。
- 新闻舆情源稳定性和去重。
- 时间切分和预测标签生成。

## 八、结论

上市公司方向的公开数据链路是可行的，核心财务数据可以从公开年报中抽取，并且可以保留页码证据。

但“查到关键词”不等于“理解舆情”，所以产品应优先做：

```text
结构化财务事实
+ 披露事件候选
+ 证据位置
+ 规则/模型复核
+ 风险概率预测
```

这次 PoC 说明：

```text
公开数据 -> 财报解析 -> 字段提取 -> 事件候选 -> 证据链
```

这条路线可以继续工程化，适合作为财税系统闭环后的第一个迁移方向。
