# 阶段 13：编排框架对照验证

日期：2026-09-17

## 目的

验证当前自研 `AsyncDagRuntime` 是否明显不如 LangGraph，并明确哪些能力应继续
自研、哪些能力适合后续引入 LangGraph。实验脚本位于：

```text
backend/experiments/langgraph_orchestration_bakeoff.py
```

LangGraph 只在隔离实验容器安装，不进入 `backend/requirements.txt`，也不进入生产镜像。

## 对照结果

使用 30 次确定性菱形 DAG，当前运行时与 LangGraph 1.2.11 的结果一致，均为 `5`。

```text
current: result=5, consistent=true, p50=17.591ms, p95=17.744ms
langgraph: result=5, consistent=true, p50=18.546ms, p95=19.411ms
```

节点重试：

```text
current: result=7, attempts=3
langgraph: result=7, attempts=3
```

检查点恢复：

```text
current: resume only executed join, result=5
langgraph: native interrupt/resume worked, final_value=11
```

能力差异：

| 能力 | 当前自定义 DAG | LangGraph |
|---|---|---|
| 确定性 DAG | 已具备 | 已具备 |
| 节点重试 | 已具备 | 已具备 |
| 缓存 | 已具备 | 生态能力更完整 |
| 检查点恢复 | 自研，已验证 | 原生更完整 |
| 人工中断/恢复 | 未实现 | 原生支持 |
| 循环图 | 明确禁止 | 原生支持 |
| 流式节点事件 | 未实现 | 原生支持 |
| 生产依赖 | 无额外框架 | 引入 `langchain-core` 等依赖 |

LangGraph 1.2.11 直接依赖包括：

```text
langchain-core
langgraph-checkpoint
langgraph-prebuilt
langgraph-sdk
pydantic
xxhash
```

## 结论

当前自研 DAG 在当前的确定性财务执行、ToolPlan、Claims、报告章节和异步节点场景中
没有表现出正确性劣势，微基准延迟还略低。因此**不应立即整体迁移**。

LangGraph 的优势集中在后续更复杂的场景：

- 人工审批和中断恢复
- 长任务持久化
- 循环 Agent/self-correcting loop
- 语音实时 Agent
- 多 Agent 图状态和流式事件

建议后续只在非关键流程做适配验证，例如“定制报告方案确认”或“语音会话状态机”，
确认收益后可保留双引擎：

```text
确定性金融执行与报告：继续 AsyncDagRuntime
复杂状态型 Agent / 人工介入：评估 LangGraph
```

本阶段不引入 LangChain/LangGraph 到生产依赖。
