## 四、确定的执行顺序

### 阶段 16：生产质量与可观测性

1. 接入 Sentry 和统一 `trace_id`。
2. 修复内部指标字段外露，统一使用中文业务标签。
3. 修复重复表达、病句和表面文案质量问题。
4. 优化 LLM、LangGraph、RAG 和报告路径的 P95 延迟。
5. 建立 checkpoint 清理、审批超时和回滚演练。
6. 建立生产指标：延迟、成本、工具命中、RAG召回、Claims数量、审批中断和报告成功率。
7. 重新运行 105 条矩阵、生产冒烟和回滚测试。


### 阶段 17：48 个指标和阈值补全

1. 按企业画像、发票、税务、交易对手、财务、社保、法律和场景综合分组。
2. 每个指标先核验源表和字段是否真实存在。
3. 源数据符合条件后补公式、粒度、时间窗口、异常规则和边界。
4. 实现确定性执行器。
5. 补齐别名、阈值需求、RAG 状态和报告章节映射。
6. 场景综合指标必须由已验证原子指标组合生成。
7. 无法实现的指标明确标记 unsupported，并写清缺失数据。

阶段 17 验收：

```text
每个指标状态明确
validated 指标全部有执行器
planned 指标不能进入 RAG
validated 指标全部有别名
threshold_required 指标全部有阈值
指标到章节和指标对到章节组合无缺口
```

### 阶段 18：RAG 混合检索

1. 安装并验证 pgvector。
2. 建立指标、阈值、业务场景、工具和章节的 embedding。
3. 使用别名精确匹配、BM25、向量检索和规则过滤的混合召回。
4. 接入 reranker。
5. 建立 Recall@K、Precision@K 和错误召回评测。
6. 只允许 validated 指标和工具进入候选集。

### 阶段 19：长对话和多 Agent

1. 优化内容级历史召回和话题消歧。
2. 增加摘要压缩、冲突检测和用户纠错。
3. 完善 memory、classification、planning、approval、execution、verification Agent。
4. 增加 finance review Agent 和 final guard Agent。
5. 控制 Agent 循环、成本、延迟和仲裁。

### 阶段 20：金融模型

1. 先 API 评测，不直接作为事实来源。
2. 评测金融术语、口径、因果复核、幻觉率、延迟和成本。
3. 再评估本地部署 7B 至 14B 模型。
4. 金融模型只能处理术语和复核，不能生成未锚定数字。

### 阶段 21：报告系统深化

1. 报告编译、章节组合、Block 组合和逐块预览。
2. Block 级缓存、锁定、替换和重生成。
3. PDF、API、前端、邮件统一使用同一棵 block tree。
4. 报告回放和 Blueprint 版本化。

### 阶段 22：语音和手机端

1. STT 接入现有语义链路。
2. TTS 只朗读通过最终验证的回复。
3. 手机系统助手通过标准 Intent 或 Deep Link 接入。
4. 增加移动端会话、后台任务、推送和隐私开关。

## 五、不能提前做的事情

- 不能先把 48 个 planned 指标做向量化。
- 不能把 planned 指标当成可用能力对外展示。
- 不能让 LangChain 替代确定性执行器。
- 不能让金融模型直接生成数字、名单或最终结论。
- 不能在延迟和表面质量问题未解决前进入语音阶段。
